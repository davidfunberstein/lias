# LIAS — אפיון ותוכנית עבודה: UI ניהול תיקים בסגנון דשבורד מודרני
**גרסה:** 1.0 | **תאריך:** 6 ביולי 2026 | **קהל יעד:** סוכן קוד / מפתח
**רפרנס עיצובי:** דשבורד "PlanIQ" (רקע בהיר, כרטיסים לבנים מעוגלים, מבטא ירוק, כרטיס כהה אחד לפעולה מרכזית)

---

## 1. רקע ומטרה

קיים כבר UI ביניים עובד ב-`LIAS/ui/index.html` (~1,200 שורות, RTL, SSE) שרץ על `http://localhost:8400` דרך `python -m LIAS.run`. הוא פונקציונלי אבל "טכני" — עץ + טבלה + לוג.

**המטרה:** שכבת תצוגה חדשה ואטרקטיבית בסגנון הרפרנס — דשבורד ניהולי שנותן לעורך הדין תמונת מצב אחת: כמה מסמכים, מה חדש, מה נכשל, מה רץ עכשיו, ומה המועדים הקרובים — בלי לגעת בקוד הקיים ובלי לשבור את ה-UI הנוכחי.

**עקרונות מחייבים (ירושה מתוכנית האב):**
1. לא נוגעים ב-`core/` וב-`LIAS/` הקיימים. ה-UI החדש הוא תוספת מקבילה.
2. SQLite (`LIAS/lias.db`) הוא מקור האמת — ה-UI החדש קורא ממנו **בקריאה בלבד**.
3. הבנייה אינה "רק לדמו": כבר מהיום הראשון הדשבורד מציג את הדאטה האמיתי הקיים (לקוחות, תיקים, 445+ מסמכים, jobs, sync_runs).
4. עברית RTL כברירת מחדל.

## 2. בחירת כלים (Stack) — החלטה והנמקה

### 2.1 אסטרטגיה דו-שלבית

| שלב | טכנולוגיה | מתי | למה |
|---|---|---|---|
| **שלב A — עכשיו (הדמו הזה)** | HTML יחיד + Vanilla JS + Chart.js (CDN) + שרת Python stdlib | מיידי | אפס התקנות, אפס build, רץ עם `python3 run_ui_demo.py`. קל לתחזוקה למי שחי בפייתון. מספיק לדשבורד, טבלאות, גרפים, SSE. |
| **שלב B — כשנדרשת מורכבות** | React 18 + Vite + Tailwind CSS + shadcn/ui + TanStack Table/Query + Recharts | כשמגיעים לצפיין PDF עם הדגשות ציטוט, ציר זמן אינטראקטיבי עם גרירה, עריכת ישויות, וירטואליזציה של אלפי שורות | אלה פיצ'רים שבהם Vanilla JS מתחיל להישבר. React הוא ממילא היעד בשלב 6 של תוכנית האב. |

**קו פרשת המים למעבר ל-React:** ברגע שמממשים אחד מאלה — צפיין PDF עם עוגני ציטוט (שלב 5–6 בתוכנית האב), טבלת מסמכים > 5,000 שורות, או עריכה דו-כיוונית (אישור/דחיית ממצאי AI) — עוברים לשלב B. עד אז שלב A מכסה הכל.

### 2.2 מה הדמו של שלב A כן נותן לטווח ארוך
- **חוזה API יציב:** כל ה-endpoints שהדמו מגדיר (§6) ישרתו אחד-לאחד גם את גרסת ה-React. ההשקעה לא נזרקת.
- **Design tokens** (§4) — צבעים, רדיוסים, טיפוגרפיה — עוברים כמו שהם ל-Tailwind config.
- **אותו מקור נתונים** — אין מיגרציה של דאטה.

### 2.3 ספריות עזר (שלב A)

| גרפים (עמודות, דונאט, sparkline) | Chart.js 4 (cdnjs) | קליל, נראה מצוין, תומך RTL |

**דפוסי UI מהרפרנס שחובה לשחזר:**
1. Top-bar לבן עם לוגו, טאבים כשה-active הוא pill ירוק, חיפוש, אווטאר.
2. שורת פתיחה: ברכה קטנה אפורה + כותרת ענק ("ברוך שובך, דוד").
3. שורת 3–4 כרטיסי KPI: כותרת קטנה, מספר ענק, ויזואליזציה מיני (sparkline/ברים) בתחתית.
4. כרטיס גרף עמודות עם עמודה אחת מודגשת בירוק ומסגרת מקווקוות סביבה.
5. **כרטיס כהה אחד בלבד** — מוקד הפעולה: אצלנו "סנכרון תיקים" עם כפתור ירוק גדול.
6. טבלת משימות עם status pills צבעוניים ותגי קובץ ירוקים (אצלנו: PDF).
7. כרטיס AI עם ברכה ושדה "שאל אותי כל דבר…" + כפתורי קיצור.

## 5. אפיון מסכים

### 5.1 מסך 1 — דשבורד (נבנה בדמו) ✅

פריסה (דסקטופ ≥1280px, גריד 12 עמודות; מובייל — עמודה אחת):

```
┌──────────────────────────── Top-bar ─────────────────────────────┐
│ לוגו LIAS │ דשבורד* תיקים מסמכים פעילות AI │ חיפוש │ ⚙ │ אווטאר │
└──────────────────────────────────────────────────────────────────┘
  מוכן לנהל את התיקים שלך?
  ברוך שובך, דוד
┌──────────┬──────────┬──────────┬──────────────────────────────┐
│ סה"כ     │ הושלמו   │ שגיאות/  │  כרטיס כהה: סנכרון           │
│ מסמכים   │ (ברים)   │ ממתינים  │  "סנכרון אחרון: לפני X"      │
│ + ספרקליין│          │ (מד)     │  [▶ הפעל סנכרון]  (→8400)   │
├──────────┴────┬──────┴─────────┼──────────────────────────────┤
│ מסמכים לפי    │ פילוח סוגי     │  כרטיס AI                    │
│ חודש (עמודות, │ מסמכים (דונאט  │  "בוקר טוב, דוד. איך אפשר    │
│ נוכחי מודגש)  │ + מקרא)        │   לעזור?" + שדה שאלה         │
├───────────────┴─┬──────────────┤  + צ'יפים: סקירת תיק /       │
│ מסמכים אחרונים  │ פעילות       │    מה חדש / מועדים            │
│ (טבלה: שם, תיק, │ (Jobs אחרונים│                               │
│ תאריך, סטטוס-   │ + סטטוס חי)  │                               │
│ pill, [PDF])    │              │                               │
└─────────────────┴──────────────┴──────────────────────────────┘
```

**מקורות נתונים לכל רכיב:**

| רכיב | שאילתה על lias.db |
|---|---|
| KPI סה"כ מסמכים | `COUNT(documents)` + פילוח לפי חודש אחרון (דלתא %) |
| KPI הושלמו / שגיאות / ממתינים | `GROUP BY download_status` (COMPLETED/ERROR/PENDING) |
| KPI תיקים פעילים | `COUNT(DISTINCT sub_cases)` |
| גרף חודשי | `submission_date` (DD/MM/YYYY) → אגרגציה לפי MM/YYYY, 12 חודשים אחרונים |
| דונאט סוגים | `doc_type` — נורמליזציה לקבוצות-על: בקשה / תגובה / החלטה / פרוטוקול / פסק דין / אחר (לפי prefix לפני " - ") |
| כרטיס סנכרון | `sync_runs` אחרון: portal, started_at, downloaded_new, hash_changed |
| מסמכים אחרונים | `ORDER BY downloaded_at DESC LIMIT 8` + join ל-sub_cases |
| פעילות | `jobs ORDER BY created_at DESC LIMIT 8` — kind, state, message |

**התנהגות:** רענון נתונים כל 15 שניות (polling; בשלב 2 — SSE מ-8400). כרטיס הסנכרון בודק אם השרת המלא (8400) חי — אם כן, הכפתור מפעיל דרכו; אם לא, מציג "הפעל את המערכת המלאה: `python -m LIAS.run`".

### 5.2 מסך 2 — סייר תיקים (שלב 1 בתוכנית העבודה)
- עמודה ימנית: עץ לקוח ← תיק ← תת-תיק, עם badge של ספירת מסמכים ונקודת "יש חדש" (מ-`whats_new`).
- מרכז: טבלת מסמכים של תת-התיק הנבחר — עמודות: שם לוגי, סוג (pill), מגיש, צד (SIDE_A/B/JUDGE כתגים צבעוניים), תאריך, עמודים, סטטוס, פעולות (פתח PDF / הצג טקסט).
- סינון: חיפוש חופשי, סוג, סטטוס, טווח תאריכים. מיון בכל עמודה.
- למעלה: כרטיס סיכום תת-תיק (סה"כ, טווח תאריכים, סנכרון אחרון, שינוי-hash אחרון).

### 5.3 מסך 3 — מסמך בודד (שלב 2)
- Drawer/מסך מפוצל: מטא-דאטה מימין, תצוגת PDF (iframe ל-`/api/doc/{id}` הקיים) משמאל, טאב טקסט OCR (`/api/doc_md/{id}` קיים).

### 5.4 מסך 4 — מוניטור פעילות (שלב 2)
- טבלת jobs חיה (SSE), progress bars, כפתור ביטול (דרך 8400), היסטוריית sync_runs עם דיפים ("ירדו 3 חדשים, hash השתנה").

### 5.5 מסך 5 — ציר זמן ומועדים (שלב 3 — תלוי בשלבים 4–5 של תוכנית האב)
- ציר אנכי לכל תת-תיק מטבלת `events`; כרטיסי deadline עם צבע לפי דחיפות; כל פריט מקושר ל-document_id+page — קליק פותח את המסמך בעמוד הנכון.

### 5.6 מסך 6 — עוזר AI (שלב 3)
- הרחבת כרטיס ה-AI לצ'אט מלא מעל `/api/ai/ask` הקיים; כל תשובה עם ציטוטים לחיצים. זה המסך שכנראה יצדיק את המעבר ל-React.

## 6. חוזה ה-API של הדמו (run_ui_demo.py, פורט 8500)

| Endpoint | מחזיר |
|---|---|
| `GET /` | index.html |
| `GET /api/dashboard` | JSON אחד עם הכל: `kpis`, `monthly[]`, `doc_types[]`, `recent_docs[]`, `jobs[]`, `last_sync`, `clients[]`, `live` (האם 8400 חי), `demo_mode` (האם fallback) |
| `GET /api/health` | `{ok, db, docs}` |

עיצוב מכוון: endpoint אגרגטיבי אחד — טעינת דשבורד בבקשה אחת. בגרסת React יפוצל לפי צורך.

**Fallback:** אם `LIAS/lias.db` לא נמצא — נתוני דמה מובנים באותו מבנה JSON בדיוק, עם דגל `demo_mode: true` ותג צהוב ב-UI. כך הדמו רץ בכל מכונה, אבל אצלך תמיד יציג דאטה אמיתי.

## 7. תוכנית עבודה

### שלב 0 — הדמו (מסירה נוכחית) ✅
- [x] `ui_demo/index.html` — דשבורד מלא לפי §5.1
- [x] `run_ui_demo.py` — שרת קריאה-בלבד, פורט 8500, fallback דמה
- **קבלה:** `python3 run_ui_demo.py` ← דפדפן נפתח ← כל הכרטיסים מציגים נתונים אמיתיים מ-lias.db; ההרצה הקיימת (`python -m LIAS.run`) לא מושפעת.

### שלב 1 — סייר תיקים (2–4 ימים)
- מסך 5.2 בתוך אותו index.html (SPA ידני: ניתוב hash `#/cases`).
- endpoints חדשים ב-run_ui_demo.py: `/api/tree`, `/api/docs?sub_case=…&q=…&type=…&status=…`.
- פתיחת PDF: אם 8400 חי — דרכו (`/api/doc/{id}`); אחרת קישור `file://` דרך reveal מקומי.
- **קבלה:** ניווט עץ מלא, סינון וחיפוש עובדים על 445+ המסמכים, פתיחת PDF עובדת.

### שלב 2 — חיבור פעולות + חי (3–5 ימים)
- Proxy מ-8500 ל-8400 לפעולות: סנכרון, OTP, פתיחת פורטל; חיבור SSE (`/events`) לעדכון חי של jobs.
- מוניטור פעילות (מסך 5.4) + דיאלוג OTP בעיצוב החדש.
- **קבלה:** אפשר לעבוד יום שלם רק מה-UI החדש; הישן נשאר כ-fallback.
- **[HUMAN-TEST]** סנכרון חי מול פורטל אמיתי.

### שלב 3 — החלטת React (נקודת עצירה מודעת)
- אם שלבים 4–5 של תוכנית האב (טקסטים, ציר זמן, סתירות) בשלים — לבצע bootstrap של Vite+React+Tailwind בתיקיית `ui/` חדשה, להעביר את ה-design tokens, ולממש מסכים 5.5–5.6 שם. חוזה ה-API כבר קיים.
- אם לא — נשארים ב-A ומוסיפים בהתמדה.

### שלב 4 — איחוד (עתידי)
- ה-UI החדש הופך לברירת המחדל ב-`python -m LIAS.run`; הישן נשמר כ-`/legacy`. אריזת Tauri לפי שלב 7 של תוכנית האב.
